## Назначение

Это шаблон структуры каталогов для Go-проектов. В нём намеренно сохранены описанные каталоги и пустые leaf-каталоги: проект, созданный из шаблона, получает стабильное исходное дерево. Это не официальный стандарт Go и не предписывает архитектуру, фреймворк, транспорт, хранилище или платформу развёртывания.

## Начало проекта

1. Создайте репозиторий из шаблона.
2. До добавления пакетов замените placeholder пути модуля:

   ```sh
   go mod edit -module=example.com/your/project
   ```

   Для публикуемого модуля используйте адрес репозитория, например `github.com/acme/project`.
3. Точки входа бинарников размещайте в `cmd/<name>/`; остальной код — в каталогах, соответствующих его ответственности.
4. После изменения импортов или зависимостей запустите `go mod tidy` и закоммитьте `go.mod` вместе с `go.sum`.
5. Запустите `make verify`. Он проверяет форматирование, `go vet` и тесты для всех Go-пакетов в репозитории. Пустой шаблон завершается успешно.

В `go.mod` указана Go 1.27.0 — минимальная версия для проектов, созданных из этой версии шаблона. Проверяйте её при принятии нового релиза Go: поддерживаются только две последние мажорные версии языка.

## Политика модулей и зависимостей

Используйте Go modules. Директива `module` — это префикс путей импорта; до публикации кода замените `example.com/project`. Пусть зависимости ведут команды Go: добавляйте или обновляйте их через `go get`, а `go mod tidy` синхронизирует метаданные модуля.

`vendor/` остаётся в шаблоне, чтобы резервировать назначение каталога, но зависимости в шаблоне не вендорятся. Создавайте его только при документированном требовании offline-сборки, воспроизводимости или политики организации:

```sh
go mod vendor
```

Не редактируйте сгенерированное содержимое `vendor/` вручную. Библиотеки обычно не коммитят вендоренные зависимости.

## Проверки качества

Корневой `Makefile` использует только инструменты Go:

```sh
make fmt-check
make vet
make test
make build
make verify
```

`make verify` — локальная проверка качества. Внешний линтер можно добавить после осознанного выбора его правил и версии; шаблон не навязывает его всем потребителям.
